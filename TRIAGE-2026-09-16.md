## One compiler class, four findings: a family's arms have different layouts

`compiler-crash`, `EMIT crash (emit-c)`, C only: the checker, the interpreter
and the JS backend accept and run every one of them. The CLI reproduces the
crash (`bend file -o out`), so it is not a worker artifact.

- `repros/comp_family_arm_layout_sig.bend`: `Error: a layout mismatch`.
  `def F0(x: Bool) -> Type` sends `False{}` to `U32` and `True{}` to a
  dependent pair `&w1: Nat -> Map<&1, Cmp>`; `def rf8(n: Bool, v: F0(n))
  -> U32` matches `n` and reads `v` in each arm (a word in one, a pair in
  the other); a def returning `F0(True{})` builds the pair through the
  index-generic `mf6(True{})`.
- `repros/comp_family_arm_layout_2.bend`: `Error: a layout mismatch`, the
  same shape over another pair of arms.
- `repros/comp_family_arm_ctor_layout.bend`: `Error: a constructor outside
  its layout: D1a`. `def F2(x: E3) -> Data` over a three-constructor enum
  sends the arms to `Either<&2, &2, D1, Sigma<..>>`, `String` and a flat
  record `D1`; `rf12(n, v: F2(n))` reads `v` per arm; the value comes
  through `mf9(E3c{})` and a def returning `F2(E3c{})`.

- `repros/comp_family_arm_char_layout.bend` (the run's fourth, not
  reduced): `Error: a constructor outside its layout: Chr`. `def F0(x:
  Bool) -> Type` sends `False{}` to `Char` (a packed constructor) and
  `True{}` to `Cmp & Map<&2, U32>`.

The common shape: a type-level def by match (`law F: for x: I; Data|Type`,
`def F(x): match x: ..`) whose arms are types of DIFFERENT runtime layouts
(a machine word, a boxed node, a flat record, a pair), a value at a closed
index that flows through a def typed `F(lit)` and through the index-generic
builder `def mf(n: I) -> F(n)`, and a reader `def rf(n: I, v: F(n))` that
matches the index and reads `v` at the arm's type. Base's own Word idiom
never crosses layouts this way (every `Word.Con<p>` is a node), so the
emitter's layout facts are computed per family, not per arm, and the value
arriving at the arm's read carries the layout of another arm.

Both messages are the emitter's own consistency checks (`a layout mismatch`,
`a constructor outside its layout`), so the failure is loud; nothing
miscompiled silently in the run.

## Generator rejects fixed during the run (46 in 21,075 seeds, all mine)

- A pair's reader put a `match` tail inside an expression (`(w + match e:
  ..)`): a match heads a def body. The witness's read now rides into every
  final expression of the evidence's read (`rd_arm(.., plus)`).
- A template argument named a unary def with a `+` parameter (`@+i:U32 ->
  U32` is not `U32 -> U32`).
- An unfinished family applied at a dependent pair's witness inside its
  own arm (`&w: E -> F(w)`) made `mf(E{})` a non-decreasing self-call: an
  unfinished family applies only at an arm's SUB-index (`IVar.sub`).
- A pair's witness re-bound reusable (`(+w, e) = x`) when its type was
  not Data: the `+` now rides only an index-term witness, the one the
  evidence names again.
- A minted def marked an index-typed parameter `+` when the enum was
  `is Type`: an index type is Data by definition now (`idx_type`).
- An `exs` claim that was itself a pair spelled bare (`&w: Nat -> Bool`
  heads a binder): the claim parenthesizes like a law row.
- Earlier the same day, before this run: a `+` binder in a template's
  lambda, `List.map`'s result at &1, and the worker sharing base's template
  instance table across requests (NOTES.md, "Worker isolation").
