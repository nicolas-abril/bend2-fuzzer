# Triage of the 2026-08-07/08 overnight run

Categorization of the 380 files in `findings/` from the run spanning
2026-08-07T21:14Z → 2026-08-08T06:04Z. The run started AFTER bend3
`da1a5913` (leaf-hoist fix, 16:36+0200), so every class below was found
at post-fix HEAD; each class was re-verified live (or noted flaky) on
2026-08-08 by re-running a representative seed.

File accounting: the 380 entries are **274 findings** (`seed-*.bend`,
verdict header + program), **105 `fm*` module siblings** (sources of the
module-split findings, not findings themselves), and `skipped/` with
**114 resource skips**. The ~400 findings collapse into **about 7 root
causes**.

**Minimal reproductions**: one verified self-contained program per
class lives in `repros/` (see `repros/README.md` for the expected
output of each).

## Findings by root cause

### 1. Clang bracket wall from the seal-combine chain — 103 (c-leg)

All identical: `fatal error: bracket nesting level exceeded maximum of
256`, always at column 272 of the offending line. Re-emitting the C for
seed `10461219231863101027` shows the cause: the final `num_combine`
fold — a flat LEFT-NESTED op2 chain `(((((v2 - v5) .^. p8) + p9) ...)`
of ~290 members — is emitted as ONE C expression. Not the dec-switch
bug: these programs' `case K+x` constants are small (max 6–248).

Repro-guided root cause (see `repros/bracket_wall.bend`): the trigger
is the chain being LET-BOUND and then used (`r = (((...))); (r + 1)`) —
that takes the UNBOXED scalar emission path (`u32 v_r = (((...`), which
has NO chunking. The same chain in tail position takes the boxed
`term_u32_add` path, where `term_cexp`'s every-64-levels temp binding
DOES chunk it (verified: the identical 280-member chain compiles in
tail position, fails let-bound). Threshold confirmed at ~256 members
(258 fails, 250 passes). This is the wall NOTES.md records as fixed
("the clang 256-bracket wall died"); the fix missed the unboxed path,
and the generator's 64-name combine chunking was deleted on that basis.

Fix looks mechanical: chunk flat op2 chains in the unboxed scalar
emitter too. Verified live at HEAD.

### 2. Compiler stack overflow (`RangeError`, stage=comp) — 86

ONE root cause: the KNOWN OPEN big-dec-switch per-peel recursion (see
NOTES.md "Known noise": bracket half fixed, the per-peel recursion not;
the bend3 issue file `comp_dec_switch_bracket_wall.md` was deleted in a
cleanup, so this still needs refiling). Every one of the 86 findings
carries a `case K+x:` with K ≈ 1600–4000 — an initial sub-split into
"~14 small programs without big K" was WRONG: those 14 hide their big-K
def inside an `fm*` module sibling (e.g. seed `2709597047027468766`'s
`tl4` with `case 3137+nk5` lives in `fm766_18`); minimization proved K
essential in each checked case.

Two crash SITES for the same cause, both per-peel-deep: `book_compile`
emission, and prep's need analysis (`def_leaves_go → def_leaves_chain →
def_need → need_seq` — the stack captured on seed `2709597047027468766`).
Seeds with K near the stack threshold are FLAKY (`6030005590461059333`
and `4070643077899025300` crashed overnight, pass on retest), so expect
count drift across bun versions / worker stack depth.

### 3. c-diverge: compiled value ≠ oracle, all F32 — 35

Every one of the 35 contains F32; 33/35 use `F32.to_u32`, 25/35
instantiate a generic at F32, 21/35 use `List(F32)`. Almost certainly
ONE word-classing family — a sibling of the two generic-F32 bugs fixed
in bend3 `3fe899d1`/`8dab9c5a`, possibly the residual per-ctor `flt`
mask that `3fe899d1` left as "one for the fuzzer". Confirmed live at
HEAD: seed `10482279896652563345` gives oracle 2966087, compiled
1126377757. **Highest-value class to minimize first** — it is the only
wrong-VALUE class in the run.

### 4. raw-reject: template def as a function value — 24 (stage=check)

23 share the exact shape: checker rejects with `expected: T -> R,
observed: @~pN:T -> R` — a def whose leading parameter carries the `~`
template sigil, passed by name as a first-class function value. Plus 1
variant: "a template is applied by name, reaching every ~ parameter".
One class; still fires at HEAD (seed `10604131800656214497`). Whether
this is a generator bug (emitting now-illegal code) or a checker bug is
a language-ruling question — per the validation recipe, every reject is
one or the other and deserves the ruling before dismissal.

### 5. "fork leaf without a continuation call" — 20 (stage=comp)

A clean `cbook_fail` at prep.ts `fin_of` (~line 1156): a fork group
whose continuation body is not a direct call. Still fires at HEAD (seed
`10375223364847774588`). One class.

### 6. `seq_apply_` never rendered — 5 (c-leg)

The emitted C calls `seq_apply_(st, ...)` — the seq body of prep's
`apply$` marker def (`$` → `_`, so the name is arity-less by
construction) — but that function is never rendered, so clang dies on
`call to undeclared function 'seq_apply_'`: a liveness/rendering gap
for `apply$`. Minimized to 15 lines (`repros/seq_apply.bend`): a def
returning a curried closure whose innermost body under-applies a
recursive def, with the call result applied over-arity in main.

### 7. batch-only / io-batch-only — 3

"No member fails alone" — but the merged-verdict headers show these are
THRESHOLD effects of other classes, not a distinct merge bug: two are
"merged crash (compile): RangeError" (class 2's stack depth, crossed
only by the merged translation unit) and one is "merged skip
(worker-timeout)" (the 20s budget, ditto). Expect them to vanish when
class 2 and the timeout budget are addressed; only then does a
surviving batch-only finding indicate a real `fuzz.ts` merge fault.

## Skipped (114) — the timeouts matter

- **86 worker timeouts at 20000ms** (65 at the raw/interpreter leg, 21
  at the sealed leg). These are NOT noise by construction: generated
  programs terminate by design, so each timeout is either an
  interpreter performance cliff or a genuine hang. Sampled seed
  `10039316440360362053` completes under a bare `--eval` in **~45s**
  with the right answer — so at least part of the population is
  slow-not-hung, and the 20s budget is simply below the tail of
  interpreter cost. But a hang class (like the `io_prebind` compiled
  hang) would land in this same bucket and be invisible; the 46/65
  raw-timeout programs containing parallel lets deserve a
  longer-timeout sweep (e.g. 120s) to separate "slow" (perf finding,
  or raise the budget) from "never terminates" (real bug).
- **21 trans-ulp**: sanctioned by ruling (libm transcendentals), no
  action.
- **7 cc-timeout**: clang runs over budget — likely the same oversized
  translation units as class 1/2; recheck after those fixes.
