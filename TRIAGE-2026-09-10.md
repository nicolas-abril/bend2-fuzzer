## Findings

### P. A packed constructor literal built from a variable — emit-c, 4 findings

Seeds 5349377474635894393 (chunk 2, par4), 9581064789741202103 (7,
par4+metal), 14282717063385672271 (13, seq) and 10598859357158262560
(16, seq). All four are `compiler-crash`, `EMIT crash (emit-c): Error: an
unbound binder: X`, where X is whatever variable fills the field — `h`
three times, `v4` once.

**Not the latest commit.** Bisected with `git bisect run` to `8627c94`
(2026-09-04, "hvm5_interp: ... and two compiler rules that let it borrow
and run on stack frames"); its parent `cb81bff` compiles the repro. It
fails identically at `7c2d194`, `e48ce06`, `60e4fc8`, `38a909f`,
`d645938`, `128a3c9`, `d0c111a`, `c606898`, `8c87d99` and `e913e65`.

The cause is that commit's packed-constructor borrow rule in
`facts_scan`'s `site` (`bend2/comp.ts`):

```js
const s = v.$ === "Var" && env.get(probe_of(v));
if (!s) {
  if (!packed(v)) { flip(lent[j] ? [ck.k, j] : null); }
  return guard(a);
}
```

The `flip` used to be unconditional. Keeping the callee's parameter
borrowed for a packed constructor literal leaves the field's variable
with no binding at the emit site.

Reduced from 83 lines to 18, in `repros/comp_packed_ctr_var_arg.bend`.
Four conditions, all needed:

1. a constructor whose own node layout is exactly one machine word
   (`lay_node(..).ks` is `["w32"]` or `[]`) — here `D0a{g0: U32}`;
2. its datatype boxed, i.e. another constructor forces a tag — here the
   recursive `D0b`. Drop `D0b`'s self field and it compiles;
3. the field spelled as a VARIABLE. `D0a{7}` compiles;
4. the value passed to a def that MATCHES on it.

No fork, bang, let, erased field or String is involved; the fuzzer's
`h` was base's own `Nat`-free `U32.read` (`base.bend:1332`), whose arm
rebuilds `SCon{h, t}`. C-emitter only: `--checkup` is silent and both the
interpreter and the JS backend print the right answer. Five neighbouring
shapes that do compile under the rule were checked and agree between the
C binary and the interpreter, so the rule is not silently miscompiling
that family. That narrowness is why the 1080-test suite passes. OPEN.

No finding of any other kind: no `leg-diverge`, `leg-timeout`,
`batch-only`, `raw-reject` or `generator-reject`, on any lane, at either
optimization level.

## Skips

2,209 persisted skip files, all interpreter worker timeouts (1,960
`raw-worker-timeout`, 249 `worker-timeout`). No `cc-timeout`, no stack
overflow, no other resource class.

**89% of them are a base.bend regression that makes `Nat.read`
uninterpretable.** 1,965 of the 2,209 call `Nat.read`. Fourteen skips
sampled at random and re-run solo on an idle machine: twelve still hit
the timeout cap, where the 2026-09-06 and 2026-09-07 triages found their
skips passed solo in about a second.

Bisected to `77eff95` (2026-09-08, "Three cheats undone ..."), which
replaced `Nat.read`'s digit-fuel guard with an overflow check:

```
def Nat.read.max() -> Nat:
  Nat.mul(U32.to_nat(16777215), U32.to_nat(16777217))
```

That is 2^48-1 built as a unary Peano `Nat`, recomputed per digit.
`Nat.divmod` is native on every compiled lane, so the compiled legs are
unaffected and the change itself is a real fix (it recovers the
[10^14, 2^48-1] range that read as `None`). But the interpreter runs
base's structural code, so the fuzzer's `term_snf` leg — the trusted
kernel, and the run's oracle — now cannot finish any program that reads
a `Nat`.

Evidence, seed 12349747344139094194:

| tree | time |
|---|---|
| `605a31e` (2026-09-06) | 0.2s |
| `4030a0e` (merge base) | 0.2s |
| `7c2d194` (HEAD) | 45.7s, timeout |
| HEAD with only `Nat.read`'s hunk reverted | 0.2s |

This is not a finding under rule zero (worker timeouts are never
findings), but it silently costs the run about 2% of its seeds and three
quarters of its throughput, and it blinds the oracle on every
`nat-showread` program. Worth a spelling of the guard that stays cheap
under structural evaluation.

The remaining 11% of skips are the known class: five sampled and re-run
solo all pass in about a second, and they are heavy in `U32.to_nat` /
`U32.from_nat`, i.e. the unary-`Nat` interpreter cost of the previous
triages. Load under 8 jobs, not a cliff.
